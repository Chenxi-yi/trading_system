# OKX Global 场景审查与实施路线 v0.2（建议稿）

日期：2026-10-20。用户要求审查既有框架并给出通向长期净盈利目标的完整步骤。
范围已确定：OKX Global；crypto 现货/合约、股票永续、x-stock 现货。
本文是设计建议和验收计划，不表示数据契约、资金风险限额或实盘权限已获批准。

## 投资目标的可检验表达

目标是成本后长期正期望、可承受的回撤与尾部风险、可持续运营；不承诺每月获利。
分别检验经济机制、统计证据、实施价值、运营稳定性。稳定运行不是稳定收益的证明。
记录两个口径：策略净 PnL（按实际成交与现金流，不重复扣滑点）和扣除数据/计算等固定开支的项目利润。
另披露税费适用口径、计价币及可行基准的机会成本；税务不凭空假设统一税率。
不设为了满足年化收益目标而反推杠杆的流程。

## 对原架构的八项修订建议

1. **产品规则独立建模**：crypto spot、linear/inverse perpetual、expiry futures、equity perpetual、tokenized-equity spot 分开。
   共用信号/订单协议，但单位、估值、保证金、资金费率、到期/滚动和公司行动规则分产品；每次新增类型单独验收。
   初始优先 USDT 线性永续，反向合约/交割后置是建议，不改变整体允许范围。
2. **底层资产与产品分离**：AAPL 参考股价、XAAPL-USDT、AAPL-USDT-SWAP 关联同一 underlying，
   分别保留价格、流动性、资金与产品风险；组合汇总净方向及 gross，价差对冲仍留基差/执行/发行人风险。
3. **日历与公司行动模块**：crypto 24/7；股票参考市场使用 exchange calendar、America/New_York、DST 和 session。
   对休市、参考价陈旧、财报、rebase、分红/拆股事件设置产品策略。不能将休市价格前填成新信息。
4. **保证金与现金管理**：独立 cash/collateral 视图，区分 NAV、可用余额、冻结资金、初始/维持保证金、
   折扣抵押品、待收付 funding 与安全缓冲。支持压力后可用抵押品测算；初期不主动开启自动借贷/复杂交叉抵押。
5. **三类验证环境**：历史回放/自建纸面模拟验证逻辑；OKX demo 验证 API/账户/订单；小额 live 校准实际费用和成交。
   三者同一策略与 Risk/账本协议，不把 demo 盈利当 live alpha。产品 demo 不支持时用回放/影子采集，不能自动跳到 live。
6. **研究/发布/运行隔离**：研究候选不能热改运行策略；冻结 strategy/config/data/schema 版本后发布。
   demo/live 分凭证、账户状态和环境；启动断言；持久化订单意图；单写者/实例锁避免两进程重复下单。
   掉线恢复先对账；回滚版本前重新核对敞口，不假设回滚代码能回滚交易。
7. **策略生命周期与账户风险汇总**：proposed → research → validated → shadow → demo → micro-live → scaled → quarantined/retired。
   每个状态都有证据和责任人；账户层限制包含手工交易/原生 Bot。无法观测的头寸使新风险许可失败关闭。
8. **AI/Kit 与资金授权隔离**：AI 协助研究、开发和解释；确定性运行程序产生订单并经风险许可。
   Kit 可选用于查询/受控模拟，原生 Bot 需委托资本/子订单监测/退出协议；不能声称每个场所生成子订单都经过本地审批。

这些职责可作为现有 domain/data/accounting/risk/monitoring 的子模块，暂不拆微服务。

## 完整推进步骤与通过条件

| 步骤 | 实际工作与交付 | 通过条件 / 不通过怎么办 |
|---|---|---|
| 0 投资授权与衡量 | Investment Mandate：本金、研究/运行预算、计价币、可接受损失、产品/杠杆/周末政策、运维责任；先填模拟环境 | PM 设定数值；未设不启动真钱。收益目标不用于倒推风险 |
| 1 账户能力审计 | 安全配置 demo 凭证，只读检查 Global 账户模式、产品、fee tier、position/margin mode；能力矩阵 | 逐产品明确支持/不支持/未知；公开列表不能代替账户授权；不擅自切账户模式 |
| 2 数据契约与持续留存 | 固定 schema/单位/可得时点/日历；首批 instruments、trade bars、mark/index、funding、spread；启动可观察采集与快照 | 覆盖报告、缺口/重复/异常检查、时钟与 confirm 检查；数据下载不等于具备历史可用时间 |
| 3 最小账本与回放 | 一个产品、信号→目标→Risk→模拟订单→成交→费用/现金/持仓→NAV；手算 golden cases | 手算对齐、现金/持仓守恒、无同 bar 偷看、资金流不当收益；失败先修底座 |
| 4 简单 baseline 研究 | R-0002：BTC/ETH/SOL Daily 简单 TSMOM，少量预注册候选；现金/买入持有/等权/风险匹配对照；现货 long-flat 与永续 long-short 分开 | 先冻结再运行；说明 beta、择时、成本与换手。首个 baseline 是测量工具，不预判有效 |
| 5 样本外与选择偏差 | chronological walk-forward、最终留出、block bootstrap、PBO/DSR 适用性、候选/参数/成本敏感性；论文逐问对应实现 | 机制/净增益/不确定性/依赖状态完整；证据不足或负结果归档，不加参数救曲线。不是每次都要机械套全套方法 |
| 6 最小组合与风险 | 从简单配置开始；总波动、gross/net、underlying 集中度、抵押品、资金费、流动性与压力情景；订单/账户硬限额 | 对组合损失与保证金冲击都能解释；参数由 PM 预算确定；违反约束则缩减或持币 |
| 7 模拟执行与运营 | 纸面 shadow + OKX demo；订单幂等、部分成交、超时未知、断连/重启、撤单和保护单核验；每日对账与告警 | 故障演练通过；未知订单/账差未解决不得加风险。低频策略另用测试场景检验故障，不刷交易次数冒充统计样本 |
| 8 股票产品专门验收 | 早期采集股票数据，在共用底座可用后测试 x-stock/股票永续；日历、参考价陈旧、公司行动/余额数量调整、订单保护恢复 | 产品历史不足则前瞻留存/影子跟踪；传统股价只用于机制研究，不当作早年 OKX 成交回测。两个产品单独晋级 |
| 9 Alpha 扩展与组合增益 | 趋势稳定测量后，carry/funding/basis、再 mean reversion、OI/订单流等；验证相对原组合的成本后增量与新风险 | 不是看单策略最高 Sharpe；若只重复风险、成本吞噬收益或机制不可交易，则拒绝。双腿策略必须另验单腿失败和保证金 |
| 10 小额 live 校准 | 单独上线审查、PM 明确资金/限额授权；受控发布；观察真实 fee/slippage/funding、订单偏差与账差 | 研究、风险、执行、运营四类审查通过；小额期重点校准实施，短期盈亏不能证明 alpha |
| 11 逐级扩容 | 在原预算内提出分档资本增量；检验容量、尾部风险、交易所敞口、恢复能力和实际净利润 | 每次扩容写 memo；有证据才扩大，恶化则降仓/隔离；不因刚盈利就加杠杆 |
| 12 持续研究与退役 | 固定周期归因与复核；数据→执行→风险→机制顺序排障；challenger 在影子环境；必要时 ML | 复杂模型按同外层样本/风险/搜索预算比较；无净增益不采用。无有效 alpha 时允许长期不交易 |

步骤存在依赖：0–3 是底座，4–6 是投资证据，7 是运营证据，10–11 是真实实施证据。
步骤 8–9 是扩展，并非第一个通过审查的 crypto 策略上线前必须完成全部产品/alpha。
步骤 2 起就积累股票与可选 OI 的前瞻数据，不必等待研究这些策略才开始记录。
步骤 7 可用未获投资晋级的测试策略验证工程，但标记为工程测试，不能作为进入 live 的投资依据。

## 第一个可运行里程碑 M1

建议：一个 BTC 产品、一个确定性 Daily 规则，完成全部运行链路；系统结构覆盖四类产品，实施逐一展开。
输出：数据报告、冻结运行版本、最小事件账本、净值与成本解释、重启对账演练、差异报告。
这说明具备可信测量与运行能力，不说明找到了 alpha。产品选择先按账户审计结果确定。

## 实盘与扩容审查必须回答

- 收益机制能否解释？为何不是单纯 beta、幸存者选择或成本漏计？
- 所有尝试是否登记？最终留出是否被消耗？结论对参数/区间/成本是否脆弱？
- 相对可行基准，等风险/等资本约束下是否有净增益？不确定性有多大？
- 最大压力下能否维持保证金和必要现金？停止/减仓是否实际可执行？
- 历史回放、shadow、demo 与 live 各验证了什么，尚未验证什么？
- 扣除实际费用、funding 和固定运营成本后是否仍有经济意义？
- 策略暂停、故障、版本更新和恢复如何记录？有哪些明确的不交易条件？

## 最近三个工作包（建议，未擅自执行）

W1：账户与风险授权草案 + demo 只读能力审计。输出账户能力矩阵，不获取/打印密钥明文。
W2：数据契约 + BTC/ETH/SOL 核心历史覆盖审计 + 股票产品前瞻采集计划。
W3：最小账本/回放 + Daily baseline 预注册；之后才进行正式策略比较。
