# PM 与研究/工程负责人的合作协议

日期：2026-10-21（Asia/Shanghai）。解释并落实 CHARTER、ARCHITECTURE 与 RESEARCH_PROTOCOL 的职责。
PM 提出目标“以 BTC 为主体开展首轮策略研究”后，Agent 对授权范围内的研究和实现连续推进负责，
主动拆解、查文献、质疑假设、实现、测试、记录失败和形成决策材料，不让 PM 逐项提示下一步。
长期目标是可持续的成本后正期望收益；任何阶段均不能把稳定盈利当作已保证的验收结果。

## 角色与责任

| 角色 | 责任 | PM 应收到什么 |
|---|---|---|
| PM（用户） | 投资目标、范围、资本/损失预算、重大取舍与实盘启动 | 可判断的证据、备选方案、明确的资金/风险决定 |
| Research Lead（Agent） | 把方向变成可反驳问题，排序研究，协调依赖，提出通过/拒绝/证据不足结论 | 研究计划、阶段报告和建议；不只列策略名字 |
| Quant Researcher（Agent） | 文献、经济机制、候选、成本后实验、失败解释 | 可复现实验与样本外报告 |
| Data Engineer / Quant Developer（Agent） | 数据血缘/质量、因果回放、账本、共享策略实现与测试 | 可运行代码、数据/环境清单、故障证据 |
| Validation / Risk（Agent） | 尝试推翻研究结论、管理选择偏差、实现拒单和限额 | 反证记录、未通过门槛、压力情景和拒单证据 |
| Execution / Operations（Agent） | 成交、对账、监控、发布/恢复、归因和退役流程 | 运行手册、演练、执行偏差与健康报告 |

以上是职责分工，不表示存在真实独立的研究院或多个已运行团队。
同一助手兼任研究和复核有共同盲点；不同复核阶段与失败记录有助于控制，但不构成独立验证。
确需外部独立复核时提出理由和具体待审材料，不能虚构已经完成外部审查。

## 从一个选题到上线：证据链

| 步骤 | Agent 必须完成 | 产物与晋级条件 |
|---|---|---|
| 1. 定义研究任务 | 整理 PM 目标、已定约束/未知项、基准、成功/失败定义 | 有版本的研究 brief；用既有决定填充，不重复索要已提供信息 |
| 2. 理论与文献 | 找原始研究/行业规则，解释收益由谁支付、反例、适用边界 | 文献笔记与可反驳假设；文献不能替代 BTC 实证 |
| 3. 数据验收 | 产品身份、历史规则、时间可得性、覆盖/修订、成本来源 | 绑定哈希的数据 manifest；无法支持某类实验则缩范围或暂缓，不填造数据 |
| 4. 冻结实验 | 候选/参数预算、基准、切分、评价指标、成本和停止规则 | 冻结 manifest 与访问记录；后改动另登记，近期已知行情不作干净留出 |
| 5. 实现与核对 | 最小账本/Risk、因果回放、信号/目标/订单/成交、成本与库存估值 | 手算对照、时序/守恒/费用/异常案例；网格需挂单和细频路径，不靠触价完美成交 |
| 6. 验证与反证 | 时序样本外、适用的 bootstrap/PBO/DSR、稳健性与极端时期 | 全候选、失败与净收益矩阵，区分经济利润与 beta；判通过/拒绝/证据不足，无单个指标自动晋级 |
| 7. 组合与完整 Risk | 资本分配、合并 BTC 暴露、现金/保证金预留、旧库存保护、降险/kill switch | 可执行风险政策及拒单测试；数值预算由 PM 决定，策略不能绕过 |
| 8. 执行工程 | 幂等订单、部分成交/超时未知、重启对账、权限隔离 | 故障演练、日志/告警与恢复手册；工程就绪与投资证据分别判断 |
| 9. Shadow / Paper / Demo | 前瞻运行、行情/持仓/资金对账、成本/执行偏差观测 | 按足够事件与场景验收；短期盈利不是 alpha 证明，资金操作需明确环境与授权 |
| 10. 小额 live | 提交具体上线版本、资金/限额、撤回方案，获 PM 明确授权后执行 | 上线清单、真实费用与成交校准；不因 demo 成功自动实盘 |
| 11. 监控、归因、复核 | 区分数据/执行故障、暴露变化、成本偏移与信号退化，按计划审查 | 收益/风险/成本归因；隔离/恢复/退役记录；扩容另作决定 |

研究被否定是有效结果；不能为交付“至少一个赚钱策略”放松成本或多重检验。
Alpha 是成本、风险和基准约束下需验证的假设，预测分数、交易规则、组合与实际 PnL 必须分开。
验证可以返回前面步骤，但查看过的留出不能在修改后重新宣称未知；新研究自由度继续累计。

## 论文在何处发挥作用

沿用 research/SOURCES.md，精读状态以该索引和对应笔记为准。

- Time Series Momentum / A Century of Evidence：提出趋势基线、经济解释与不同市场状态问题，不把跨资产历史收益迁移成 BTC 结论。
- The Probability of Backtest Overfitting / Deflated Sharpe Ratio：在完整候选记录上诊断选择偏差；PBO 不是未来亏损概率或上线开关。
- Trading Costs of Asset Pricing Anomalies / Harris：把换手和可实现成本纳入研究；机构股票参数不能直接套 crypto。
- Almgren–Chriss：理解成交速度、价格风险和冲击之间的权衡；小资金低频先校准简单模型，不强行实现复杂优化器。
- Covariance shrinkage / Universal Portfolio Shrinkage：组合估计误差与权重问题；多个 BTC 策略的相关性需实测，单币不必过早复杂化。
- Deep Momentum Networks：只有简单基线和统一验证成熟后研究额外样本外净增益。

论文按阻碍当前决策的问题精读/复现，不要求先学完所有论文才建立第一个可运行基线。
没有合适实证依据的网格候选，应标为待验证机制，不能硬贴论文给它背书。

## 自主推进与 PM 决策

已授权研究范围内的数据公开读取、文献、代码、可逆修正、离线实验、检查与仓库记录，由 Agent 主动推进。
研究冻结属于执行研究规范，不要求 PM 审每个参数；提前公布并记录假设，PM 纠正时按变更处理。
仅在缺失输入会实质改变研究有效性、风险预算或授权边界时询问，并并行推进不依赖回答的工作。
新增付费资源、扩大资本/产品/杠杆风险、转账、账户模式变化和实盘启动由 PM 决定；
已有明确授权不重复确认。需要决定时先给具体可审查方案、证据、风险和回退动作。

架构允许推进后续准备，不表示所有未来账户操作都已获授权；当前实际连接仍是 Demo 只读，未获实盘订单授权。
数据缺口只阻塞依赖它的产品/实验，不无限期阻止最小账本、其他独立验证或运行准备。

## 日常交付与连续性

每个有实质进展的工作单元向 PM 报告：新增能力、证据/运行 ID、被推翻的假设、未通过项、下一动作和所需 PM 决定。
进展以可运行实现/可复现实验/可审查决定衡量；文档是保存证据与方向的工具，不代替实际研究。
TASKS、PROJECT_STATE、研究记录、sessions、Git 同步维护；原始数据/私有运行状态另行备份。
跨对话通过读取项目记录恢复；常驻交易依赖明确部署的进程、主机与响应人，当前均未完成验收。
