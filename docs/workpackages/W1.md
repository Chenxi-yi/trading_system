# W1：账户能力与投资边界

工作包已由 PM 接受。任务状态统一维护在根目录 TASKS.md，本文件保存执行顺序与验收标准。

## 目的与交付

查清 OKX Global 模拟账户实际支持哪些产品、何种模式、哪些费率与单位，
并明确研究/模拟阶段的资本口径。输出：

1. docs/INVESTMENT_MANDATE.md：已确认原则与待决策项。
2. docs/ACCOUNT_CAPABILITIES.md：脱敏的能力矩阵；未测项明确写未测。
3. 受限只读审计器、离线检查与本机私有审计证据（已实现；见 tools/ 与 runtime/）。
4. W1 验收 memo：首批可用产品、未知项、降级方案与 W2 输入，见 W1_REVIEW.md；交易前保护仍待验收。

## 执行顺序

1. PM 提供模拟规模/预算意向；待定可以保留。实盘本金与限额后续单独决定。
2. 按 docs/OKX_DEMO_SETUP.md 创建 demo 只读凭证并在本机配置；不在聊天传密钥。
3. Agent 编写并离线核验只读审计器；此项可与前两项独立推进。
4. 本机签名 GET：时钟/认证、账户模式、账户可用 instruments、产品费率与模式。
5. 将公开产品与账户可用产品进行映射；区分 crypto spot、SWAP、FUTURES、equity SWAP、x-stock SPOT。
6. 建立脱敏结果和私有证据引用；确认 W2 首批数据合同。

## 审计控制

- 只允许已核验的只读 GET 路径；签名与认证材料只在本机使用，不进入命令行参数/日志/报告。
- 强制模拟 header/environment；检测到 live 凭证/环境不匹配或状态未知则拒绝。
- 不切账户/仓位/保证金模式；不挂测试订单来推测权限。
- 账户清单可见不等于下单已测通，分别记录可见性、权限与实际订单链路验证状态。
- 没有 demo 支持的产品记录限制；未来用回放/影子验证，不自动尝试 live。
- 报告不提交 UID、余额、持仓、签名或其他私有原始响应。原始证据在 ignored runtime/ 本机保存。

## 通过条件

产品身份/单位明确；权限与模式有证据；费率口径及限制明确；未知项有处理方案；
模拟资本与预算口径足以开展下一阶段（可延后实盘数值）；没有新增实盘权限。
如果账户不支持某类产品，W1 可以以“限制已确认”完成，不假装该产品已具备模拟交易能力。
