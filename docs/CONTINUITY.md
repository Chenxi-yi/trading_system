# 持续性与恢复

代码仓库是项目事实来源；聊天是讨论界面，不是唯一存档。
AGENTS.md 是 Codex 可识别的项目指令；其他文件靠该指令显式读取，不宣称会自动载入全部历史。
官方说明：https://learn.chatgpt.com/docs/agent-configuration/agents-md

## 四种记忆

1. CHARTER / AGENTS：长期目标、原则、工作规则，保持简短稳定。
2. PROJECT_STATE：当前阶段、已验证事实、下一步、未决事项；始终指向最新状态。
3. ADR / sessions：为什么这样做、替代方案、变更与检验证据；历史只追加或标明取代。
4. experiments / manifests：机器可追溯的代码、数据、参数、环境和结果，不依赖文字记忆。

## 日常协议

开始：读取状态和相关 ADR，核对 Git SHA、dirty 状态与文档是否一致，确认本次问题。
过程中：重要假设立即落盘；长任务在阶段完成时保存，不等对话最后一刻。
结束：更新状态，写交接，记录通过/失败/未运行检查，审阅 diff，提交本地检查点。
需要同步时推送已配置的私有远端；不要将“已本地提交”写成“已异地备份”。
中断恢复：先检查工作树和日志，不假设最后一句聊天代表代码真实状态。

## Git 和 GitHub

本地 Git 立即使用。GitHub 私有仓库用于跨设备、审查、Issues、CI 和远端代码备份。
不连接 GitHub 也能研究；连接不会让新聊天自动拥有历史内容，仍要读项目文件。
已按用户授权关联 origin：https://github.com/Chenxi-yi/trading_system.git。
main 跟踪 origin/main；2026-10-20 已完成首次推送。仓库可见性未核验。
原始数据、运行账本、研究大文件与秘密不提交 Git，使用独立备份及内容哈希清单；
数据清单包含来源、范围、版本、校验和、获取方式和存储位置。
私有仓库也不是密钥保险箱。交易密钥仅运行环境注入，日志脱敏。
环境 lockfile、schema migration、代码和小型可复现 fixture 进入版本控制。

## 防止记忆越来越长

PROJECT_STATE 只放当前工作集；完成事项归档至 session，长期理由放 ADR。
每个研究有 ID，状态文档引用 ID，不重复拷贝整篇报告。
规则冲突时记录并解决，不偷偷重写历史；用户新决定更新章程/ADR并标明取代关系。
每个里程碑做恢复演练：从干净 checkout + 数据 manifest + 环境锁重新生成指定报告。

## 新对话恢复提示

“继续 Personal Mini Quant Fund。先读取本项目 AGENTS.md、PROJECT_STATE.md，
核对 Git 状态与最新交接，再按下一项工作推进；不要从零重写架构。”

必须让新对话能访问同一项目目录/仓库。如果是在无法访问本地文件的环境，
需提供这些状态文件或仓库访问，不能保证仅凭项目名称恢复。
