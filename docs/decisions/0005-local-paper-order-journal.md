# ADR-0005：本机 paper 订单与预算日志

日期：2026-10-21。状态：本机合成案例已实现；不代表 OKX Demo 或实盘准入。

## 问题与决定

纯函数风控不能防止两个策略同时花掉一笔现金，也不能处理提交超时后预算该不该释放。
增加 `execution/paper_store.py`，以 SQLite `BEGIN IMMEDIATE` 串行化修改；金额使用整数微 USDT 和聪。
每个策略先分配固定资金，分配合计就是 Bot 初始资金；不从账户余额自动扩容。
事件有单调序列与本机UTC记录时刻；合成事件不伪装真实交易所event_time或发布时间。
本模块只接受 `paper` 环境，不导入交易所客户端，不存在发送订单方法。

## 已有约束

- 本机订单意图持久化与预算/库存预留在同一事务中完成。
- 买入预留最坏限价与费用缓冲；卖出只能使用策略新获得、未被预留的 BTC。
- 旧 BTC 仅作为不可出售的保护基线参加对账，不计 Bot 净值或可卖库存。
- client ID 和 fill ID 幂等；重复 ID 内容冲突拒绝；异常成交整笔回滚。
- 提交超时进入 unknown，保留全部尚未消耗预留并停止新增意图。
- 部分成交只消耗实际费用与成交资金；明确确认撤单后释放剩余预留。
- 停机后仍接受已知订单成交入账；停止新增风险不等于忽略成交。
- 每次打开已有数据库均停机；须以合成 broker 快照重新对账，显式恢复。
- 对账不符持久停机；未知订单未解决不能恢复；恢复不会自动取消未知订单。
- 初始本金损失限制以已对账估值价格计算，允许持有库存的减仓；限额由调用方明确传入。

## 不能据此声称已经完成的工作

这是合成 BTC 现货的工程基础，不是完整交易 Risk Engine 或真实账户保护。
当前固定分配无动态调拨/净额成交归属；不支持永续保证金、股票或借贷。
尚未连接真实账户基线、场所订单查询/迟到成交对账、余额币种规则、产品 tick/min、
行情质量与发布延迟、组合 gross/net、完整集中度/波动/尾部风险、监控告警和运维值守。
本机 cancel/reject 的输入表示模拟 broker 明确确认，不能映射成“网络超时便撤单成功”。
撤单后收到此前未知的成交会拒绝并要求对账；生产适配器必须实现迟到成交恢复，不能丢弃回报。
无自动减仓/紧急清仓，数据库损坏和磁盘故障需后续恢复设计；SQLite 事务不代替备份。
对账快照和 mark 在本机由测试提供，不是已验证的 OKX 事实。该模块不授权任何场所订单。

## 验收证据

`tests/test_paper_store.py`：12 项，包括并发抢占预算、重复/冲突回报、部分成交与撤单、
unknown 重启、保护库存、过期快照、停机后成交、初始本金损失和进程未提交退出后的回滚。
`tests/test_replay_causality.py` 另检验价格/mark/funding 未来变化不改变历史交易前缀。
测试通过证明这些案例的实现行为，不证明硬件故障全覆盖或长期策略有效。
