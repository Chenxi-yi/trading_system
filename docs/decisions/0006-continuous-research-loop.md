# ADR-0006：有累计记忆的持续研究循环

日期：2026-10-21。状态：PM明确要求“未通过就继续提出新想法，直到有策略跑出来”，已授权后续研究。

## 决定

继续研究，不以第一批失败为项目终点。原BTC-NIGHT-001的20配置预算和结果永久保留；
新授权允许独立登记后续批次，不允许改旧样本、旧参数或旧门槛把失败变成功。
“初级所以失败”不是已证实原因；复杂模型也必须通过对照展示增量。

流程：失败归因/论文 → 可反驳机制 → 数据可得性 → 小批登记 → 代码/因果/账本测试 →
开发和已知历史挑战 → 成本/状态/选择诊断 → 淘汰或前瞻观察 → 工程验收 → PM晋级。
未通过则产出下一条新信息需求或机制，不能只是搜索更多窗口直到Sharpe过线。

## 搜索与证据规则

- 单批最多8个alpha配置和4个固定消融/基准；一天最多2个新批次，单次定时运行最多推进1批。
  这些是本轮自动研究资源边界，不限制查文献、故障修复或等待期间的数据/前瞻工作。
- registry累计全部批次、配置、对照、诊断场景与人工选择；不同批次的试验数不能归零。
- 每3批新增研究做一次方法/数据/收益机制审计；若只有调参没有新信息，转数据/文献/工程，不继续同类暴力搜索。
- 2020–2026已接触的BTC历史现在是适应性开发/挑战资料，即使新策略以前没跑过，也不是新的独立留出。
- 每批可以用单批PBO/块bootstrap诊断，但不能声称它们修复了跨批次、人工启发和可选停止偏差。
- 不修改第一批保守门槛；如以后研究治理要改变，单独解释经济理由、在结果前登记，并保留旧口径比较。
- 真正前瞻必须绑定冻结代码/规则、未观察到的新bar及实际采集/决策/可执行时刻；不得在四小时唤醒时回填过去一小时开盘成交。
- “历史筛查候选”“前瞻观察中”“研究达标”“模拟工程准入”“实盘”分别记录。
  找到历史赢家时转入反证/前瞻，不能以不断搜索的停止时刻作为盈利证明。

## 运行

复用原heartbeat btc，改为每4小时在本对话续跑。事实入口仍为TASKS；循环机器检查点与注册表在research/loop。
模型负责在每次触发时读取证据、提出并实现有理由的下一步；不是一个能自行无限发明策略的Python函数。
本地文件任务依赖电脑开启、应用运行、网络与额度可用。调度不是全天常驻交易服务。
常规无变化保持安静；通知有意义的新发现、候选晋级、失败的运行/数据或确需PM处理的事项。
仅使用现有免费数据与本机资源；不新增付费、不交易、不转账、不改账户模式、不安装未知服务。
有候选通过研究及工程准入时暂停搜索并向PM提交具体模拟方案；实盘仍须明确授权。
PM可随时暂停/改方向；真正外部阻塞或额度不足保留检查点，避免忙等和重复启动。
